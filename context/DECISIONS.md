# Согласованные решения

## ADR-001 — Инструменты проекта

- Статус: принято, 2026-11-07.
- C++20, CMake >= 3.20, CTest; ядро оформляется отдельной библиотекой.
- Отчёт: LuaLaTeX + `fontspec` + Biber, единая точка входа `report/main.tex`.
- Причина: требования задания и переносимая автоматизированная сборка.

## ADR-002 — Разделение владения

- Статус: принято, 2026-11-07.
- Файлы и роли закреплены в `AGENTS.md` и `TASKS.md`.
- Изменения чужой зоны и утверждённых контрактов выполняются только после
  записанного согласования.

## ADR-003 — Предложение первоначальной нормальной формы API

- Статус: согласовано для ветки реализации, 2026-11-08.
- Модель максимизации и минимизации с ограничениями `Ax <= b` и
  неотрицательными переменными, `n >= 1`, `m >= 0`. Допускаются
  отрицательные правые части, для которых требуется первая фаза.
- Агенты 1 и 2 используют единую постановку и пример. Агент 2 отвечает
  за ядро и его описание, агент 3 — за интеграцию, публичный API, CLI и тесты.
- Плотная таблица, две фазы, правило Бланда, единый счётчик поворотов.
  Добавлен статус `numerical_failure` для численных сбоев.

## ADR-004 — Обмен между CLI и экспериментами

- Статус: согласовано для ветки реализации, 2026-11-08.
- Вход — текстовый `LP1`, выход — одна строка JSON. Разбор и примеры
  описаны в [CONTRACTS.md](CONTRACTS.md).
- Эталон для экспериментов — SciPy/HiGHS с методом внутренних точек.
  Сохраняются входные задачи, сценарий, версия зависимостей и фактический
  снимок результатов, использованный в отчёте.

## ADR-005 — Общая ветка реализации задания

- Статус: принято для текущей работы, 2026-11-08.
- По поручению пользователя полный проект подготовлен параллельно.
  Агент 1 ведёт постановку, агент 2 — алгоритм и ядро, агент 4 —
  эксперименты. Интегратор ведёт CLI, тесты, LaTeX и общий контроль.
- Публикация и передача на проверку через ветку
  `feature/complete-simplex-project`.

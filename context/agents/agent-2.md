  искусственным переменным. Если вспомогательная цель оказалась

- В среде Ubuntu под WSL выполнены 24 целевые проверки на максимизацию,

  дал оптимум `10¹²`, а `0 x ≤ −10⁻¹²` распознан как несовместный.
- Независимая проверка 10 000 ограниченных задач с целыми коэффициентами

### Рецензия для агента № 1

- Постановка согласуется с ядром: непрерывные переменные, максимум или
  минимум `c^T x` при `Ax ≤ b`, `x ≥ 0`, `n ≥ 1`, `m ≥ 0`.
  Допустимы отрицательные правые части. Например, `−x ≤ −1` и `x ≤ 2`
  дают отрезок `[1, 2]`, поэтому нулевой план для этих строк недопустим.
- Перебор вершин даёт конечный оптимум при ограниченной цели. Для
  неограниченной области в разделе корректно предусмотрена проверка
  улучшающих направлений. Гарантия правила Бланда отнесена к точной
  арифметике. Сравнение с методами внутренней точки учитывает структуру
  матрицы и точность.
- Проверены вершины общего примера: `(0,0)`, `(2,0)`, `(2,2)`, `(1,3)`,
  `(0,3)`. Значения цели равны `0, 6, 10, 9, 6`. Из оценки
  `3x₁ + 2x₂ = 2(x₁ + x₂) + x₁ ≤ 10` следует единственность оптимума:
  равенство требует одновременно `x₁ + x₂ = 4` и `x₁ = 2`.
- В разделе 1 `d` обозначает направление луча, а `u_j` используется
  при расщеплении свободной переменной. В существующем разделе 2 эти
  символы обозначают вектор внутренней цели и искусственную переменную.
  Предлагаю в разделе 2 обозначить их как `c̃` и `α_i` соответственно.
- В обзоре перебора выражение «часть систем вырождена» можно уточнить
  как «часть наборов имеет линейно зависимые нормали», чтобы отличить
  такие наборы от вырожденного базисного допустимого плана.

  существующего API `simplex::solve(const LinearProgram&, const SolveOptions&)` с

  таблица — `long double`. Возможные статусы: `optimal`, `infeasible`,
  `unbounded`, `iteration_limit`, `invalid_input`, `numerical_failure`.
  Координаты и цель выдаются при `optimal`. Способ подключения раздела
  и размещение тестов согласуются с интегратором.
- Агент № 4. Для сверки LP1/JSON нужны допустимый пример с отрицательным
  `b_i`, несовместный и неограниченный случаи, вырождение и задачу
  без строк ограничений. Проверить общий счётчик обеих фаз, включая вывод
  искусственных переменных, и нулевой лимит при немедленном оптимуме.
  При нескольких оптимумах сравнивать допустимость и цель. Контролировать
  относительную невязку строк: для каждой строки сравнить превышение
  `max(0, A_i x − b_i)` с `ε (|b_i| + Σ_j |a_ij x_j|)`, где
  `ε = 1e-9` по умолчанию. Отдельный случай `10⁻¹² x ≤ 1`
  проверяет, что малый ненулевой коэффициент ограничивает рост.
